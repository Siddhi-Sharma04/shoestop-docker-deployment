1. Project Title & Description

ShoeStop is a full-stack MERN e-commerce web application containerized using Docker and deployed on Render.com. The original application had hardcoded URLs, development-only configuration, and no containerization. This project transforms it into a production-ready, containerized, cloud-deployed system.

6 & 7. Docker Implementation - Frontend

Frontend Dockerfile (Multi-Stage)

# Stage 1: Build React application with Vite
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci

ARG VITE_API_URL=http://localhost:5000
ENV VITE_API_URL=$VITE_API_URL

COPY . .
RUN npm run build        # Produces /app/dist/

# Stage 2: Serve compiled assets with Nginx
FROM nginx:1.25-alpine AS runner
RUN rm /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=5s CMD wget ... http://localhost/health
CMD ["nginx", "-g", "daemon off;"]

Nginx SPA Config

server {
    listen 80;
    root /usr/share/nginx/html;
    gzip on;                           # Compress assets
    location ~* \.(js|css|jpg|png)$ {
        expires 1y;                    # Long-term cache for assets
        add_header Cache-Control "public, immutable";
    }
    location / {
        try_files $uri $uri/ /index.html;  # SPA routing fallback
    }
    location /health { return 200 "healthy\n"; }
}

8. Backend Containerization

# Stage 1: Install production dependencies only
FROM node:18-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

# Stage 2: Minimal production runtime
FROM node:18-alpine AS runner

# Security: non-root user
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN rm -f .env         # Remove any committed secrets
RUN chown -R appuser:appgroup /app
USER appuser

EXPOSE 5000
HEALTHCHECK --interval=30s --timeout=10s CMD wget ... http://localhost:5000/ || exit 1
CMD ["node", "server.js"]    # Production command (NOT nodemon)

9. MongoDB Configuration

Option A: Containerized MongoDB (Default)

mongo:

10. Docker Compose Orchestration

version: "3.9"
services:
  mongo:
    image: mongo:7.0
    volumes: [ mongo-data:/data/db ]
    healthcheck: { test: mongosh ping, interval: 30s }

  backend:
    build: { context: ./backend }
    depends_on: { mongo: { condition: service_healthy } }
    environment:
      - MONGO_URI=${MONGO_URI:-mongodb://admin:admin123@mongo:27017/shoestop}
      - JWT_SECRET=${JWT_SECRET:-mysecret}
    ports: [ "5000:5000" ]
    healthcheck: { test: wget http://localhost:5000/, interval: 30s }

  frontend:
    build:
      context: ./frontend
      args: { VITE_API_URL: "${VITE_API_URL:-http://localhost:5000}" }
    depends_on: { backend: { condition: service_healthy } }
    ports: [ "3000:80" ]

volumes:
  mongo-data: { name: shoestop-mongo-data }

networks:
  shoestop-network: { driver: bridge }
Startup order: 1. MongoDB (waits for health) → 2. Backend (waits for health) → 3. Frontend

12. Cloud Deployment Process (Render.com)

Backend Deployment

  1. Push project to GitHub
  2. Go to render.com → New → Web Service
  3. Select repo, Root Directory: backend, Runtime: Docker
  4. Add env vars: MONGO_URI, JWT_SECRET, PORT=5000, CORS_ORIGIN=*
  5. Deploy → Copy URL: https://shoestop-backend.onrender.com

Frontend Deployment

  1. New → Web Service, Root Directory: frontend, Runtime: Docker
  2. Add build arg: VITE_API_URL=https://shoestop-backend.onrender.com
  3. Deploy → Public URL: https://shoestop-frontend.onrender.com
Public URL: https://shoestop-frontend.onrender.com (active after deployment)
